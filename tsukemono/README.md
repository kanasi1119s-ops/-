# 漬物！最強の漬物への道 — 最小版（試作）

塩分・温度・日数を調整して「ちょうど良い味」を探す試行が楽しいか、だけを確かめるための最小版。
HTML/JavaScript（依存パッケージなし）。

## 動かす

```
cd tsukemono
npm start          # http://localhost:8080/  （味の確認表: /explorer.html）
npm test           # 味のモデル・売上・ゲーム進行・素材のテスト
npm run survey     # 条件を変えた結果の一覧を端末に表示
npm run balance    # 決まった作戦で自動で遊ばせ、もうけを比べる（バランスの点検）
npm run e2e        # 画面の通し確認（タイトル→仕込み→一日のまとめ→販売・投資・常連・セーブ・スマホ幅。Playwright が必要）
npm run build      # テストプレイ用に1つのHTMLにまとめる → dist/tsukemono-standalone.html（そのまま開ける）
```

`file://` では ES Modules が動かないので、開発中は `npm start` の簡易サーバー経由で開く。`npm run build` で作った1ファイル版は、ダブルクリックで開ける（esbuild を npx で取ってくるのでネットが必要）。

## 画面と音

- タイトル →「はじめる」で店先へ。帳場（季節・日付・時間・天気・時間帯の進みの帯と一時停止・評判の星・所持金）、店先、会話窓とコマンド。PC（幅1000px以上で、その方が店先を大きくできるとき）は店先を左に大きく置き、帳場・会話窓・コマンドを右の帯にまとめる横並び。スマホは縦積み。
- **時間制**: 朝→昼→夕→夜が実時間で自動的に進む（`calendar.realSeconds`: 朝・昼・夕 各90秒、夜30秒で1日 約5分。設定の「時間の速さ」×0.5〜×4で変えられる）。窓を開いている間・仕込みなどの場面の間・帳場の ❚❚ を押している間は止まる。夜が明けると「店じまい」の窓（止まる）。
- コマンド: 仕込む／売る／樽／ぬか床／店／帳面／休む／設定、それと **とばす**（次の時間帯へ）。それぞれ窓が開く。
- 店先の樽の札（◎=食べ頃、!=白い膜、数字=漬けた日数、＋=空き樽）を押すと、その樽の窓が開く（味見・手入れ・売る・捨てる）。
- 夜が明けると「店じまい」の窓で、その日のお客・売上・評判の変化・新しい常連・図鑑をまとめて見せる。「休む」で数日まとめて進められる。
- 売れるとお金が浮かんで「チャリン」、常連になる・図鑑に載ると知らせが出る。
- 雨・雪の日、お客さんは傘を差す（`assets/sprites.js` の `umbrella`）。横から見た8本骨の傘を計算で描く: 手前に見える骨は奥行きで縮み、光は左上から当たってパネルごとに明るさが変わる。すそは骨の先のあいだが少し上がり、てっぺんに石突き、骨の先に露先。色は人ごとの傘の色から陰・骨・ふちどりの色を作る。柄は人の後ろに描くので、頭の後ろを通って手のほうへ下りて見える。雪の日はかさの上に雪が積もる。
- 音は `src/audio.js`。音源ファイルを使わず、ブラウザの合成音で鳴らす。BGMはタイトル・昼・夕方・夜の4曲（三味線・箏・尺八・拍子木・太鼓っぽい音色、陽音階と都節）。曲はMMLで書いてあるので、音符の文字列を書き換えれば変えられる。雨・雪の日は雨音が入る。効果音は仕込み（水の音）、手入れ、お金、図鑑、一日の終わりなど。
- 歩き: ユーザーの「ドット絵エディタ」（`tools/pixel-editor.html`。claude.ai のアーティファクトと同じもの）をブラウザで動かして作った16コマ。脚は股関節・膝関節・足関節の3つの関節で回す（もも・すね・足の3部品）。左右の脚は半周ずれて交互に出し、立っている足の裏はいつも地面の行につける。腕は脚と逆に振り、手に持ったかごは手と一緒に動く。肩掛けカバン・リュック・つばさ・しっぽ・ほうき・日傘・釣り竿は動かさない（腕やかごに付いていかない）。
  - エディタに「回す（角度・軸）…」（Shift+T）を足した。選んだ部分を、軸のドットを中心に角度だけ回す（RotSprite: 8倍に拡大してから回し、3×3の多数決で戻すので線が崩れにくい）。
  - 手順は `tools/editor_rig_walk.mjs`: 元の絵を開く → レイヤー（影・奥の腕・奥の脚3つ・手前の脚3つ・胴・すそ・カバン・手前の腕・かご）に切り分ける → かごや腕の後ろに隠れていた脚の付け根・服・カバンを「えんぴつ」で描き足す → 16コマに複製 → コマごとに部品を「すべて選択→回す→矢印キーで関節の位置へ→Enter」→ 地面より下を消す → 動かしてできたすき間を「手直し」レイヤーに描く → 影レイヤーに足元の楕円 → 確かめ（足の裏が地面の行・接地2ドット以上・すき間なし・かごとカバンのドット数が全コマ同じ）→ オニオンスキンで写真・再生 → 「シート」「GIF」で書き出し。
  - 部品の切り分けは人ごとの「部品の表」`assets/editor/<名前>.parts.txt`（元の絵と同じ大きさの文字の表。T 胴・A 手前の腕・R 奥の腕・K かご・G カバン・S スカート・N 手前の脚・F 奥の脚、. は消す）。1ドットずつ、拡大した元の絵と見比べて決めた（袖と服の境の線、カバンのひもや前側、髪、ベルトからさがる鎖や刀など）。
  - かごの後ろに隠れていた手前の脚は、元の絵の脚はそのまま使い、隠れていた所だけ左右のふちの線のあいだを塗って描き足す（`hideFill`。ひざ当て・ガーター・ブーツなどは段ごとの色で）。膝・足首は、上の部品のドットを下の部品にも少し描いておき（関節のふた）、曲げても欠けない。
  - スカート・袴・ドレス・パレオは、腰を軸に前と後ろの2枚に分け、それぞれ前の脚・後ろの脚に合わせて回す（`skirt`）。開いた所はスカートの裏の色が見える。かごの後ろに隠れていたスカートも描き足す（色は一色にせず、その行の見えている服の色を続けるので、かごが動いても陰の段がつながる。`closeGap` でかごの角の外もふちの線まで埋める）。
  - 関節の位置・描き足しは人ごとに `tools/walk_joints.json`、回す角度の表は `tools/walk_rig.py`（エディタの結果は表と1ドットも違わないことを確かめる）、ゲームへの取りこみは `tools/walk_import.py`。部品を動かしてできたすき間は、まわり8マスで多い色で埋める。
  - 太さ戻し: 部品を回すと、ふちのドット（1マスを9つの点で見て5つに満たない所）が削れて、細い脚は1〜2割やせる。4つ以上で残す甘い回し方との差（削れたふちのドット）を、脚の部品の横で上に何も重なっていない所にだけ「手直し」で描き戻す（元の絵より太くはしない）。
  - 足まわりのそうじ: 部品に分ける前に、脚ごとにほとんど同じ色（へだたり24以下）を多い方の色にそろえ、脚のおもな色から遠い色のつぶ（白いにじみ・灰色のつぶ）はまわりの色に描きなおす（回したときにふちがつながり、色のつぶが出ない）。動かしたあとも、腰より下で、まわりに同じ色が1つもない1ドットはまわりの色に、はなれた1ドットは消しゴムで消す。ゲームに取りこむときに、体から離れた小さなかけら（64ドット未満）も消す（`walk_import.py` の `drop_crumbs`）。
  - エディタの作品は `assets/editor/<名前>.json`（エディタの「作品を開く」で開いて直せる）、GIF・作業画面の写真・確かめの結果は `docs/walk/`。動画は `node scripts/record.mjs`（docs/walk/walk.mp4）。
- 樽の中身: 樽ごとに口の内側の楕円を測り（`tools/barrel_tops.py`、縁と値札にはかぶらない）、奥の板・底・漬け汁・野菜を重ねた下絵を作って、エディタの鉛筆で1色ずつ塗った（`tools/editor_barrels.mjs`）。空の樽も同じ。作品は `assets/editor/barrels/`。
- 吹き出し: お客のひとことは、店先の画面の上に大きな文字（明朝の太字）で重ねる（画面の中の小さな文字はやめた）。
- 見た目（和）: 地は紺の青海波、店先は焦げ茶の木枠、窓は和紙に墨の文字、コマンドは木札、大事なところは朱。見出しは筆文字（Yuji Syuku）、本文は明朝（Zen Old Mincho）。日付は漢数字、天気と時間は「晴」「朝」の札、評判は朱の丸5つ。

| 段階 | 中身 | 場所 |
| --- | --- | --- |
| 1. 味のモデル | 画面なしの計算。テストで挙動を確認 | `src/model.js` `src/sales.js` `src/game.js` `tests/` |
| 2. 確認用の表示 | 条件を変えた結果の一覧 | `scripts/survey.js` `explorer.html` |
| 4. 経営 | 季節の仕入れ値・旬・置き場所・評判・投資（冷蔵庫・室・樽）・常連客 | `src/game.js` `tests/business.test.js` `tests/regulars.test.js` |
| 5. 種類の拡張 | 大根・野沢菜・なす・かぶ・にんじん・キャベツ、たくあん・野沢菜漬、調味8種（昆布・唐辛子・ざらめ・ゆず・生姜・赤しそ・からし・酒粕）と相性、図鑑 | `src/config.js` `src/model.js` `tests/varieties.test.js` |
| 3. 最小版の画面 | 仕込み→熟成→販売が1周。ドット絵と動き | `index.html` `src/main.js` `src/render.js` `src/world.js` |
| 絵のトレース | 参考画像をドット絵（768×432・背景192色・人物48色）に起こす | `tools/trace.py` → `assets/img/` `assets/trace.js` |

- 係数・基準値は **`src/config.js` の1か所**。出典のある値は【出典】、ないものは【仮置き】とコメント。
- 漬物は **`data/pickles.js` の定義**から作る（段階A）。1件の定義に、野菜・工程（`steps`）・塩分の目安（`saltHint` と `salt`）・温度の目安（`tempHint` と `temp`）・食べ頃の日数（`ripeAt`）・必要な店のレベル（`level`）・解放の条件（`unlock`、段階Cで使う）・調味との相性（`affinity`）を持つ。**定義を1件足すだけで**、仕込みの窓・図鑑・お客の反応に新しい漬物が出る（`tests/pickles-data.test.js` で確かめる）。必須の項目が抜けていたり id がかぶっていると、読みこむときにエラーで知らせる。
- ぬか床の手入れは **`data/nuka.js` の定義**（段階B）。`NUKA_CARE` の1件が「いつ使うか（`when`）・値段・効き目（`effects`）・説明」を持ち、1件足すだけでぬか床の窓に手入れの札が増える。床の変化そのもの（放っておくと 白い膜 → 酸っぱい → 傷む、ぬか漬けで水っぽくなる、捨て漬け）は `src/model.js` の `nukaStep`／`nukaApply`、係数は `src/config.js` の `nuka`。
- 作り方の解放は段階C。**店のレベル**は `data/levels.js`（必要な経験・肩書き・置ける樽の数・地方の枠）、**設備**（置き場所と道具: 屋外・土間・冷蔵庫・室・壺・加温室・燻製小屋）は `data/facilities.js`。隠れた漬物は `data/pickles.js` の `unlock`（`via` = ひらめき／失敗から／教わる、`hint` = 噂、`when` = 条件の組み合わせ、`line` = ひらめいたときの一言）で定義し、条件の判定は `src/unlock.js` の `unmet`。**条件が合ってもレベルが足りなければ仕込めない**（`level`。二重の鍵）。台詞は `data/quips.js`。
- 仮置きの一覧は `node scripts/placeholders.js > docs/placeholders.md` で作り直せる（`src/config.js` と `data/` の【仮置き】を、項目・値・理由つきで並べる）。
- 絵と動きの定義は `assets/`（`img/` トレースした絵、`scene.js` 配置、`characters.js` 人物と色違い、`animations.js` コマ送り、`themes.js` 季節・時間・天気、`sprites.js` 小物）。
- ズーム・拡大縮小はしない。canvas は 768×432 を **整数倍** で表示（ぼかさない）。画面より狭いスマホだけは幅に合わせて縮める（ぼかさないが、ドットの大きさが少し不ぞろいになる）。
- ドットの細かさは 768×432（`tools/trace.py` の `SC = 2`。はじめは 384×216 だった）。参考画像は 1024×572 なので、背景は 1.33 分の 1、人物は約 1.6 分の 1 に縮めるだけで、目や眼鏡、看板の字、樽のたがが元の絵どおりに残る。座標を書いた定数は 384×216 の値を `SC` 倍して使う（trace.py・barrel_tops.py）か、2倍した値を直接書いてある（scene.js・render.js・main.js・characters.js・animations.js・world.js・walk_joints.json・walk_prep.py）。文字で描いた小物（傘・太陽・月・水たまり）は `SPRITE_SCALE = 2` で2倍にして描く。

1. 384×216 に縮小し、128色に減色（元絵のドットの大きさに近い）。
2. ポーズ集（無地の背景）から店主7・女性7・おばあちゃん8・頭巾のおばあちゃん8・おじいさん8・男の子8・女の子8・セーラー服8・学生服8・ブレザー8・紫の服8・スーツ8・サングラス8・バレー部8・サッカー部8・レースクイーン8・空手着8・お侍さん8・水着8・日傘8・釣り人8・バックパッカー8・騎士8・宇宙人8・ケンタウロス8・魔女8・悪魔8のポーズを切り抜き、店先と同じくらいの背丈（72〜77px）に縮める。足元の影と、枠の外から入っている手（`POSE_ERASE`）は落とす。
   子ども3人とかごは店先の絵から GrabCut で切り抜く。
   縮め方（背景と人物）: 2倍の大きさ（768×432）にしてからは、背景は面積の平均、人物はランチョス（`sharp_resize`。面積の平均より目・眼鏡・線がはっきり残る）で縮めて減色する（背景240色・人物48色、既定）。1マスに元の絵の数ドットしか入らないので平均でも輪郭はぼけず、多数決のようにドットがぽつぽつ立たない（スーツのような一色の広い面がなめらかに、元の絵に近く出る）。ぽつんと1ドットだけ違う色も勝手にならさない（元の絵の模様かもしれないため）。`TRACE_VOTE=1 python3 tools/trace.py` で前の「多数決」縮小（`vote_downscale`。1マスごとに面積のいちばん多い色をとる。暗い線は1.6倍に数える）に切りかえられる。形（透明かどうか）は面積の平均で決めるので前と同じ。足元は、地面の影（灰色）を落とすときに白い靴下や白い靴の陰まで落とさないよう、灰色のうち「人物から離れていて、その列の下に人物の画素がないもの」を確実な影とし、その色と同じ灰色だけを落とす（`drop_ground_shadow`。影は青みがかった灰色のことも赤みがかった灰色のこともあるので色相は見ない）。脚と靴のあいだの、背景と見分けのつかない明るい隙間（白い靴下）は上下に人物の画素があれば埋める（`bridge_feet`）。ふちに残った白い背景のにじみ（輪郭線の外にはみ出した白に近いドット）は `tools/defringe.py` で取る。頭（あごより上）と足元はさわらない（白い髪のハイライトや頭巾のふち、靴下は輪郭線の外に出ているのが本来の絵）（歩きのコマも取りこむときに同じく）。おばあちゃん2人は、どのポーズも襟とスカートの色をポーズ0（歩きの元の絵）の色にそろえる（`OUTFIT`）。おばあちゃん（1人目）はポーズ集で頭巾のあるポーズとないポーズが混ざっているので、頭巾のあるポーズ4の頭巾を、顔の位置で合わせて髪と入れかえ、全ポーズ頭巾にそろえる（`HOOD`。顔はそのまま）。同じ人でもポーズ集のポーズごとに服や肌の色が少しずつ違う（女性のスカートがピンク、おばあちゃんの中の着物が赤紫、上着が水色など）ので、人ごとに部分（スカート・着物・白い上着・肌）を決めて、ポーズ0の同じ部分の色に合わせる（`ZONES`。色相をずらし彩度・明るさを比で合わせるか、白い服と肌はポーズ0のその部分の色から明るさの近い色を選ぶ）。そろえて増えた色は、使う数の少ない色から近い色にまとめて48色にする（`limit_colors`）。頭巾の差しかえでは髪の色のドットだけを消し、顔の輪郭線は残す。頭巾の色はそのポーズにもともとある色から選ぶ。輪郭線は「元の絵の線があるふちのマスを線の色で先に濃く入れる → 中は面積の平均で塗る → 最後にふちの線を、店先になじむ暗い中間色に少しだけ寄せる」の順で作る（`outline_pass`）。ふちの線は内側の色には寄せず、薄めたあとも内側より必ず暗く残すので、白い頭巾や白い服でも線が消えない。
3. 背景は人のいない絵をそのまま縮小・減色（人物を抜いた跡の補修は不要）。
4. のれん・大根・唐辛子を抜き出して、揺らせるようにする。浮いている雲も抜き出して流す。
5. 売り場の樽3つの口を、空／白菜／きゅうりの3通りに作る。空は透明にする（時間帯・天気で空を描き替える）。

GUIのドット絵エディタはこの環境では使えないため、上の手順をスクリプトで行い、座標の指定（`HINTS` `FORCE`）で手直しした。

動き（`assets/animations.js`）: ポーズ集の人はポーズの絵を差し替えるコマ（歩く2コマ、財布を出す→受け取る、店主はあいさつ→トングで取る→袋に詰める→渡す→お辞儀）。待っている・話しているあいだの動きは、絵全体を上下させず、腰から上だけを1ドット上げる呼吸（`up: -1`。足は地面についたまま。上がった分は腰の行をのばして埋める）。トングで取る・塩をふるときは腰から上が2ドット沈み、胴が脚にかぶさってひざを曲げた見えになる（`up: 2`）。
通りがかりの子どもは1枚の絵を「頭・胴・左脚・右脚」に分け、1〜2ドットずらしたコマで動かす。客は列に並んで順番を待つ。
季節: 夏の昼の絵を基準に、草木・田んぼ・地面・屋根の色を置き換える（`assets/themes.js`）。時間帯は色のかけ合わせ。
- 動き（`render.js` / `world.js`）は状態を読むだけで、書き換えない。「動きを止める」を入れても遊びは同じ。

## 遊び方

1. 樽を選び、漬物・野菜・塩分・**置き場所**・**個数**を決めて「仕込む」。温度は置き場所で決まる（屋外＝外気温+3℃、土間＝外気温−2℃、冷蔵庫＝いつでも4℃、室＝いつでも22℃）。野菜の値段は季節で変わり、**旬**の野菜は安くて質（食感）が良い。
   個数は1〜24個（`sales.barrelCapacity`）を数値で選ぶ（−6／−／数字／＋／＋6 と 6・12・18・24 の札）。標準は6個（たくあんは18個）で、野菜と塩の代金は標準の個数に対する比で増減する（調味は樽ごとに1回）。多く仕込むほど安く多く売れるが、売れ残ると酸っぱくなる。
2. 時間は自動で進んで熟成する（急ぐときは「とばす」「休む」）。「味見」で今の味を確認。
3. 食べ頃（または客の好みの熟し具合）の樽を「**店先に出す**」。出しておくと、店が開いている朝・昼・夕の時間帯ごとに、名前のない客がランダムに来て（天気と評判しだい。時間帯の中で間をおいて順に来る）、満足度に応じた値段で買う。売り切れると樽は空になり、別の樽を出す。傷んだ樽は全員が買わない。
   客の好みは「あっさり好き・しょっぱめ好き・酸っぱい好き・食感重視・通」のどれか（来るたびにランダム）。見た目は好みに合う人が少し出やすい（おばあちゃんはあっさり好き、など。遊びには影響しない）。
4. 画面の「次にやること」が、今の状態に合わせて次の一手を案内する（`src/guide.js`）。
5. 手入れ（段階3）: 白菜漬けは放っておくと**白い膜**が張って味が落ちる（10℃以上で数日、4℃では35日ほど出ない）。「手入れ」で取れる。
   **ぬか床**は店にひとつ。かき混ぜないと酸っぱくなり（26℃以上は特に早い）膜も張る。毎日「かき混ぜる」と熟成して、**ぬか漬け**（きゅうり・白菜、一晩〜1日）の風味が深くなる。酸っぱくなったら「塩を足す」。
   段階Bで床の手入れを細かくした: 床には**酸味・白い膜・水っぽさ・傷み・旨味・熟成度**がある。放っておくと 白い膜 → 酸っぱい → 傷む の順に進む（26℃以上は酸味が先に来る）。ぬか漬けを漬けるほど野菜の水で**水っぽく**なり（酸っぱくなりやすく、塩味が薄まる）、「ぬかと塩を足す」でしまる。酸っぱいときは 塩・からし・卵の殻。**捨て漬け**（キャベツの芯など）を3〜4日ごとに替えないと傷みが進む。傷んだ床で漬けると傷みリスクが上がり風味が落ちる。昆布・赤唐辛子・煮干し・実山椒・ゆずの皮で**旨味**を足すと風味が深くなる（旨味は少しずつ抜ける）。
   **レベルとひらめき（段階C）**: 売ると店の**経験**がたまり（とても満足されると2倍、図鑑・ひらめき・初めての成功でも増える）、**レベル**が上がると樽の5個目・壺・加温室・燻製小屋と、地方の漬物の枠が開く。はじめに知っている作り方は5つ。残りは**レシピ帳**（帳面）に「？？？」で載り、噂がほのめかす組み合わせで仕込むと**ひらめく**: からし漬け（なす＋からし）、柴漬け（夏のなす＋赤しそ）、粕漬け（酒粕で涼しい所に10日）、古漬け（漬物を酸っぱくしすぎる＝失敗から気づく）。あと一つ条件が足りないと「なにか思いつきそうで…」と知らせる。ひらめいてもレベルが足りなければまだ挑めない。売ってお客に「うまい！」（満足60以上）と言わせると、その作り方がレシピ帳で**埋まり**、うまくいった樽が増えるほど**腕前**（うろ覚え→人並み→得意→十八番→門外不出）が上がって風味と食感が良くなる。
   **難癖のお客（クレーマー）**: 店を開けた時間帯ごとに約1割の確率で、なんにでもケチをつけるお客（いつも同じ人）が来る。味がどうであれ必ずどこかに文句を言い（「白菜が四角い」「うますぎて他の店で買えなくなる」など）、要求を突きつけて帰る。難癖を聞いたあとのお客は満足度が少し下がる。対応は 平謝り（評判−1、相手が図太くなる）／おまけ（1個タダ、味をしめる）／毅然と説明（店のレベル・味の良さで通りやすい。成功で評判+2、失敗で−4）／常連の助け舟（常連がいる時間帯だけ）／出入り禁止（レベル3から。季節ひとつ来なくなるが、変装して戻ってくる）。放っておくと評判−3。備えは「店」で買える 品質表示の札（説明が通りやすい）・お客様の声ノート（評判の下がり方が半分）・にらみ招き猫（レベル3、来る確率が半分）。図太さを0まで下げると改心して常連（通）になり、しばらくすると別の難癖のお客が現れる。台詞と対応は `data/claimer.js`。
   **経営（段階D）**: 野菜の**相場**は毎日変わり（季節×日ごとの揺れ±15%）、1日に1つ**特売**（4割引き）が出ることがある。「仕入れ」で安い日に買っておくと仕込みで在庫から先に使う（2日を過ぎると品質が落ち、7日を過ぎると傷んで捨てる）。**季節の行事**（お花見・梅雨入り・お盆・たくあんの仕込みどき・歳末・正月）は客足・売り値・人気の漬物・野菜の値段が変わる。毎朝**店の維持費**（150円＋樽1つ40円）。払えないと大家さんが待ってくれる（お金はマイナスにならない）。**従業員**（アルバイト＝毎朝ぬか床と膜の手入れ／看板店員＝お客×1.25／職人の弟子＝腕前2倍）は毎朝お給料、払えないと辞める。**契約農家**と契約すると新しい野菜（赤かぶ）。7日に1度**行商人**が来て、まだ知らない作り方の巻物を売る。たくあん・粕漬け・古漬けは**寝かせるほど高く売れる**（熟成もの）。お客には**年代**（若い人は薄味、お年寄りはしょっぱめ）があり、年がたつと若い人が増え、みんなの好む塩味も下がる（**減塩の流れ**）。**常連**には名前がつき、3回来ると好みがわかり、とても満足させるたびに絆が深まって**その人の話**（3章ずつ）が聞ける。定義は `data/events.js`（行事）・`data/staff.js`（従業員）・`data/stories.js`（年代・常連の名前と物語）、仕組みは `src/business.js`。
   **本編の物語「最強の漬物への道」**: 馬鹿らしいことを、どこまでも真剣に語る本筋。序章「遺言」（先代は『最強の漬物を作れ』と言い残して温泉へ）→ 第一章「三文字」→ 第二章「宿敵」（向かいに『漬物帝国』と漬物男爵）→ 第三章「矢文」（審査員長は町内会長の猫・タマ殿の漬物対決）→ 第四章「伝説の重石」（裏山の祠の、ただの石）→ 第五章「最終決戦」→ 終章「最強の漬物」。幕間に「ぬか床は語る」（ぬか床が熟した夜の夢）と「雇われ難癖」（難癖のお客の改心で明かされる真実）。章は店のレベル・日数・最初の成功・ぬか床・難癖のお客の改心などで始まり、対決などの**課題**（7〜90日以内に、満足80以上のお客を5人／寝かせた漬物を売る／三種の漬物で満足82以上）を果たすと先へ進む。負けると負けの章が出て、しばらくしてやり直し。語りは窓で一行ずつ「次へ」で読み、帳面の「物語」で読み返せる。章は `data/saga.js` に1件足せば増やせ、進め方は `src/saga.js`。
   **種類の拡張（段階E）**: 野菜は `data/vegetables.js` の定義（水分量・塩の入り方・漬かる速さ・食感の変わり方・傷みやすさ・値段・旬）。葉物は塩の入りが早く、かたい根や皮の厚い実は遅い。水分の多い野菜ほど塩味が薄まり、ぬか床を水っぽくする。野菜に**梅・白瓜・みょうが**を追加（樽の中身の絵は `tools/veg_tops.py` で色替えした仮の絵）。**たくあん**は「干す日数」（0〜14日、目安5〜10日）を選べ、干すほど食感と塩味が締まって傷みにくくなる（干しているあいだ樽はふさがる）。**梅干し**（壺がいる、塩15〜20%、約1か月、いつまでも置けて寝かせるほど高い）は、梅が梅酢から出てくるとカビやすいので、「樽」から重石を直して沈め、カビは清潔なスプーンで取る。調味の相性は売るとわかり、**レシピ帳**に漬物ごとの相性（◎△✕）がたまっていく。
6. 経営（段階4）: 「店」の欄に**評判**（0〜100）。満足したお客が多いほど上がり、評判が高いほど客が来る。傷んだものを出すと大きく下がる。とても満足したお客はときどき**常連**になり、同じ顔でまた来て少し多く払う（がっかりさせ続けると離れる）。お金がたまったら**冷蔵庫・室を買う**、**樽を増やす**（最大5個。4・5個目は店先の右の樽）。
7. 種類と調味（段階5）: 野菜に**大根・野沢菜・なす**、漬物に**たくあん**（約1か月以上・大樽で18個）と**野沢菜漬**（冬の屋外で約10日）を追加。浅漬け・ぬか漬けはなす・大根でも漬けられる。
   仕込みで**調味**（昆布・唐辛子・ざらめ・ゆず）を2つまで足せる。漬物との相性（◎合う・△ふつう・✕合わない）は、売ってみると仕込みの欄に出る。相性が良いと風味が深まり、どのお客も少し喜ぶ。唐辛子は傷みにくくする、ざらめは塩味を和らげる。
   売った組み合わせ（漬物×野菜×調味）は**図鑑**に載る（全121通り）。
8. 「練習モード」（既定ON）では、仕込む前に予測（食べ頃までの日数と味）が見える。切ると自分で探る遊びになる。

「確認用の操作」で季節・時間帯・天気の見た目を固定して確かめられる（遊びには影響しない）。

セーブ: 操作のたびにブラウザ（localStorage）へ自動保存し、次に開くと続きから。保存できない環境でも遊べる（保存しないだけ）。壊れたセーブは読まずに最初から。「確認用の操作」の「最初からやり直す」で消せる。

## 味のモデル

発酵の進み（標準日/日）＝ 基準 × 温度の係数 × 塩分の係数 × 野菜の係数。白菜を塩3%・20℃で漬けると1日で1標準日進む。

- 酸味 = 100·p/(p+7)（p=進み）。食べ頃（白菜漬け p=7）で約50。
- 塩味 = 塩分 × 回り具合（半日〜1日で回る）。塩6%で100。
- 食感 = 野菜ごとの初期値 × exp(−p/τ)。傷みが高いと下がる。
- 風味の複雑さ = 漬物の上限 × √熟度 × 温度の係数（18〜22℃で最大、高温ほど下がる）。
- 傷みのリスク = 1−exp(−危険度×日数)。低塩分・高温ほど危険度が高い。
- 段階：まだ早い／食べ頃／過熟ぎみ／酸っぱすぎ（進み÷食べ頃の比で決める）。

## 仮置きの一覧（出典にない値。すべて `src/config.js` で変えられる）

**味のモデル**
- 酸味の式の半飽和点 `acidHalfProgress = 7`。
- 塩の回り `saltAbsorbTauDays = 0.5` 日、塩味100とする塩分 `saltFullPct = 6`%。
- 風味の複雑さ：18℃未満は1℃ごと−2%、22℃超は1℃ごと−4%、下限15%。浅漬けの上限35、白菜漬けは100。
- 傷みのリスク全般：基準 `0.01`/日、塩分表（1%=8, 2%=3, 3%=1, 5%=0.3, 10%=0.05, 20%=0）、温度表（4℃=0.1 … 40℃=10）、野菜係数。3%・20℃で7日→約7%。
- 食感：白菜（初期80, τ=20）、きゅうり（初期95, τ=8）、傷み100%で半分。
- きゅうり：発酵 ×1.1、傷み ×1.3。
- 補間は線形（企画書の表の「間は補間」の方法を線形と決めた）。

**漬物**
- 食べ頃の幅：白菜漬け＝比0.85〜1.3（6〜9日）、酸っぱすぎは比1.8（約12.6日）超。浅漬け＝比0.5〜3、酸っぱすぎは比5超（食べ頃の中心は1標準日）。
- 価格：浅漬け250円、白菜漬け500円。仕入れ：白菜500円、きゅうり300円、塩代 塩分1%あたり10円。1樽の標準は6個（たくあん18個）で、仕込みで1〜24個（`sales.barrelCapacity`）を選べる。野菜と塩の代金は標準の個数に対する比で増減（調味は樽ごとに1回）。所持金の初期値2000円。

**客・売上**
- 客は名前なしでランダムに来る（最大5人、1人ずつ来店率で判定）。来るたびに好みのタイプ（あっさり好き・しょっぱめ好き・酸っぱい好き・食感重視・通）のどれかがランダムに付く。
- タイプごとの理想の味（酸味・塩味・食感・複雑さ）と重視度、好きな漬物の種類。
- 満足度＝100−(重み付きズレ)×1.7、好きな種類+8、未熟は×0.5〜1.0、過熟×0.92・酸っぱすぎ×0.7、傷みリスクは期待値で最大×0.2。
- 満足度40未満は買わない。支払額＝定価×(0.6〜1.3)（満足度に比例）。
- 来る人数: 最大5人、1人ずつ来店率で判定（平均約4人）。見た目は好みのタイプが合う人が4倍選ばれやすい（`LIKE_BOOST`）。
- 傷みの判定は樽ごとに販売のたび1回。傷んでいたら全員が買わず樽は空になる。

**季節・時間・天気**
- 外気温の初期値：春15・夏28・秋15・冬5℃（指示書の例のとおり）。
- 1日=4区切り（朝・昼・夕・夜）、1季節=28日。夜は閉店（仕込みはできる）。朝=仕込み／昼=熟成／夕=販売は目安で、強制はしない。
- 時間制の実時間 `calendar.realSeconds`：朝・昼・夕 各90秒、夜30秒（×1で1日 約5分。設定の速さ ×0.5〜×4 で割る）。店先に出した樽は時間帯ごとに客を引き、その客は時間帯の残り時間の7割に散らして来る（最初の1人は1〜2秒後、以降は2.6秒以上あける）。
- 天気の出やすさ（冬だけ雪が出る等）、来店率＝0.8×天気（晴1.0／雨0.5／雪0.4）×時間（朝0.7／昼・夕1.0／夜0）。
- 客の好みの季節差：夏は塩味−12・酸味−5、冬は塩味+12（春秋は変化なし）。

**手入れ（段階3）**
- 白い膜の増え方（1日あたり。4℃ 0.008 → 20℃ 0.08 → 30℃ 0.15）、見える量0.3、味に響く量0.15〜、満足度最大×0.5。出典は「4℃では35日まで出ず、10〜25℃で早く出る」のみ。
- ぬか床: 塩分7%（4〜12%）、ぬか漬け1樽ごとに塩分−0.3%、かき混ぜないと1日に酸味+0.1（20℃）〜+0.3（30℃、26℃以上で急増）、かき混ぜると酸味−0.35・膜が取れる、塩を足す（+1%・10円・酸味−0.25）、毎日かき混ぜて14日で熟成度最大。出典は「適温20〜25℃、26℃以上で乳酸が出やすい」「酸っぱくなる原因は高温・かき混ぜ不足・塩分不足」「塩を足すと回復」。
- ぬか漬け: 食べ頃1標準日弱（20℃のきゅうりで約1.6日）、野菜が吸う塩はぬか床の4割、風味の深さは床の熟成度で40〜100%、床の酸味1で酸味+40、価格300円。

**経営（段階4）**
- 仕入れ値の季節倍率：白菜 春1.1・夏1.3・秋0.9・冬0.7、きゅうり 春1.0・夏0.7・秋1.1・冬1.4。倍率1未満を「旬」と表示。野菜の質＝2−倍率（0.85〜1.15）で、初めの食感にかかる。
- 評判：初期50、満足度50を境に1人ごと±(満足度−50)×0.08、傷んだものを出すと−6。来店率は評判0で×0.6、100で×1.4。
- 置き場所：屋外＝外気温+3℃、土間＝外気温−2℃（最初から使える）、冷蔵庫4℃（3000円）、室22℃（4000円）。
- 樽：最初3個、4個目2500円・5個目4000円。
- 常連客：満足度80以上で買った客が3割の確率で常連に（最大6人）。店を開けるたびに1人0.45×天気×時間の確率で来る（評判に関係なし）。1割多く払う。満足度50未満か傷んだものが2回続くと離れる。見た目は常連ごとに決まった人。
- 案内は「仕込み代×樽の数×2」を残せるときだけ投資をすすめる。

**種類と調味（段階5）**
- 大根（漬かり×0.8、食感90・τ80、傷み×0.8、400円、冬が旬）、野沢菜（450円、晩秋〜冬）、なす（漬かり×1.1、食感70・τ10、傷み×1.2、350円、夏が旬）。
- たくあん: 食べ頃は20標準日（大根は漬かりが遅いので、塩5%・室22℃で約36日）、酸味の半飽和点20、風味の上限80、900円、1樽18個、食べ頃の幅は比0.9〜4、酸っぱすぎは比6。出典は「約1か月以上、干し大根を塩・ぬか・ざらめ・唐辛子・昆布で本漬け」。**干す工程はまだ入れていない**。
- 野沢菜漬: 食べ頃3標準日（冬の屋外8℃で約10日。出典は寒い時期に「2〜3週間」）、風味の上限70、450円、塩の目安2.5〜3%は出典どおり。
- 白菜漬けの風味の上限を100→85にした（昆布などで深まる余地）。
- 調味の効き目: 昆布 風味+14（60円）、唐辛子 風味+8・傷み×0.85（30円）、ざらめ 風味+10・塩味−10・酸味−5（40円）、ゆず 風味+10・酸味+6（80円）。相性が良いとそのまま、ふつうは半分、悪いと風味−15。相性の良い調味1つにつき満足度+6（悪いと−6）。どれも漬かるほど効く。
- 相性の表（どの組み合わせが合うか）は、出典の材料（たくあん・ぬか床の旨味）をもとにした仮置き。
- 客の好きな漬物を複数に（しょっぱめ好き・通・食感重視がたくあん、酸っぱい好きがぬか漬け、食感重視が野沢菜漬）。
- 樽の中身の絵（大根・野沢菜・なす・たくあん）は、トレースした白菜・きゅうりの絵の色を置き換えて作った（`tools/veg_tops.py`）。
